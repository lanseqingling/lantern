# Agent

Lantern Agent 是漫画工作台中的创作协作者。它理解用户当前在做什么，选择必要上下文，提出建议或调用受控创作能力，并把结果以可理解、可拒绝、可恢复的方式交还给用户。它不替用户拥有作品，也不以自动完成整话为目标。

本文是 Agent 产品行为、交互循环、上下文、任务、候选和分阶段实现的事实源。作品结构与写入不变量见 [LCD](./lcd.md)，工作台呈现见[编辑器体验](./editor.md)；可执行 schema、Capability 与持久化字段仍以代码为准。

## 1. 设计目标与边界

Agent 需要同时满足四个目标：

- **理解当前创作**：从用户输入、选择、显式引用和作品状态中识别真实目标，减少重复说明。
- **行动可预期**：执行前说明焦点、范围和关键参考；执行后说明实际结果与未完成部分。
- **结果可控制**：生成、结构、多对象和高风险变化先成为 Candidate，用户决定应用、继续修订或丢弃。
- **持续推进**：对话、任务与候选可以跨页面恢复，但每一步都基于最新工作稿和固定资源版本。

Agent 不是任意数据库写入器、JSON Patch 生成器或隐藏工作流引擎。它只能调用登记过的语义 Capability，不能直接拼装 `WorkspaceCommand`、修改 LCD、调用 Prisma，或让模型决定对象 ID、事务和 revision。对话、任务、进度和候选都不是作品事实；只有合法 ChangeSet 才能产生新的 WorkingRevision。

## 2. 一轮协作如何完成

每条用户消息都经过同一条循环：

```text
理解输入与当前焦点
  → 判断意图、目标、作用范围和风险
  → 选择并冻结本轮上下文
  → 直接回复 / 追问 / 请求确认 / 执行
  → 校验工具结果
  → 呈现回答或 Candidate
  → 用户应用、继续修订、丢弃或撤销
```

### 2.1 每轮决策

| 决策 | 何时使用 | 是否创建任务 |
|---|---|---|
| 直接回复 | 寒暄、产品说明、创作讨论、作品分析，或不需要工具的建议 | 否 |
| 补充信息 | 缺失信息会显著改变目标、范围、结果或安全性，且没有可靠默认值 | 否 |
| 确认行动 | 跨格、整页、整话、结构变化、覆盖已确认内容，或系统对范围只有高风险推断 | 确认后决定 |
| 受控执行 | 目标与范围明确，所需 Capability 已开放，前置条件满足 | 仅异步或可重试动作创建 |

决策不能只依赖关键词。Interaction Resolver 先解析用户明确表达，再结合引用、选择、当前焦点和会话约束；模型可以参与语义判断，但作用范围上限、风险确认和 Capability 权限由确定性规则兜底。

追问只询问阻塞行动的信息，一次不超过三个短问题。可以采用安全默认值时直接推进，并在执行说明中写明默认值；例如“创建一个人物”不要求用户先选中画格，“只改表情”却没有目标图片时必须先让用户指定对象。

### 2.2 行动的呈现

Agent 在对话中只呈现对用户有用的过程，不展示内部思维链或供应商调用细节：

1. **行动说明**：一句话复述目标，并显示目标对象、作用范围和主要参考；需要确认时同时说明风险。
2. **执行进度**：只报告排队、生成、校验、等待确认、失败或取消等有意义节点，不用虚假的逐字“思考过程”占据对话。
3. **结果说明**：直接回答给出结论；作品变化给出 Candidate 卡片、变更摘要、影响范围和比较入口。
4. **下一步**：只提供当前可用动作，例如应用、继续修订、丢弃、重试或基于最新工作稿重新生成。

任务运行时旧作品保持可见，用户可以停止任务。停止、失败或校验不通过都不能创建空白候选，也不能改变工作稿。

### 2.3 结果进入作品

Agent 结果按风险进入两条路径：

- 单对象、确定性、低风险且用户指令明确的动作，可以通过同源 Capability 直接提交一个原子 ChangeSet；对话显示已完成内容和“撤销”入口。
- 生成、结构、多对象、跨层和其他高风险动作必须形成 Candidate。应用前只是暂存结果，不属于作品。

Candidate 支持以下操作：

- **预览**：组合当前工作稿与候选，比较原稿和新结果，不创建 revision。
- **应用**：重新校验 owner、目标、Capability 权限和 base revision，再以一个原子 ChangeSet 进入工作稿。
- **继续修订**：把当前候选作为显式输入生成派生候选；新结果成功前保留原候选，且不会把原候选先写入作品。
- **丢弃**：只结束候选生命周期，不改变工作稿。
- **撤销已应用结果**：走普通 Undo，产生新的工作稿 revision，不把旧候选伪装成“未应用”。

目标在任务期间已经变化且无法安全重放时，Candidate 标记为 stale。系统不提供绕过 revision 校验的强制覆盖，只能基于最新工作稿重新规划。

## 3. Agent 模式与运行结构

### 3.1 产品模式

模式决定一次协作如何组织，不改变作品协议和安全边界：

| 模式 | 适用情况 | 交互特点 |
|---|---|---|
| 对话协作 | 默认模式；问答、建议、创建资产、局部生成和普通编辑 | 每轮动态选择直接回复、追问、确认或执行，不要求用户预先选择固定模式 |
| 聚焦精修 | 围绕一个画格、图片、对白或 Candidate 连续比较和修改 | 固定目标与保护范围，允许多轮派生候选和前后对比 |
| Workflow | 续写、整页编排、整话生产等有依赖的长流程 | 显示阶段、检查点与剩余步骤，用户可以暂停、恢复或在阶段间修改方向 |

输入区的“创作”“资产”等快捷意图只是提示，不是强制路由。系统应优先从自然语言与当前焦点判断本轮行为；只有用户主动进入聚焦精修或 Workflow 时，模式才成为跨轮约束。

P0 只开放对话协作。聚焦精修和 Workflow 在底层 Capability、上下文和候选链稳定后进入 P2，不能用独立旧任务处理器提前复制一套规则。

### 3.2 运行职责

```text
Interaction Resolver
  → Context Planner / Builder
  → Tool Planner
  → Capability Registry
  → Executor + Validator
  → Response / Candidate Presenter
```

- **Interaction Resolver** 产出本轮决策、目标、范围、保护约束与风险等级。
- **Context Planner** 根据目标和候选工具声明需要哪些事实；Builder 负责查询、裁剪、固定版本并生成 snapshot。
- **Tool Planner** 只输出已登记 Capability 的调用计划和依赖关系，不输出任意作品命令。
- **Capability Registry** 统一维护输入 schema、作用范围、前置条件、风险、预览策略、Undo 策略和 Agent 权限。
- **Executor** 校验参数和 base revision，执行 dry-run 或正式调用；模型不能绕过它直接写作品。
- **Presenter** 把真实读取的上下文、执行结果、遗漏和错误转换成简洁用户反馈。

工具循环可以根据工具结果继续调用下一步，但必须有最大步数、总耗时和作用范围上限。任何一步扩大范围、改变保护约束或进入更高风险等级，都要重新确认，而不是沿用上一轮授权。

### 3.3 权限与风险

Capability 的 Agent 权限分为 `disabled`、`observe`、`preview` 和 `execute`。新 Capability 默认禁用，只有具备 schema、前置条件、原子撤销、测试和可解释结果后才能开放。

| 风险 | 典型动作 | 默认处理 |
|---|---|---|
| 只读 | 分析页面节奏、解释对象或提供建议 | 直接回复 |
| 低风险 | 明确目标上的确定性单对象编辑 | 可直接 ChangeSet，完成后可撤销 |
| 中风险 | 生成资产、改单格图片、改写对白、局部多对象调整 | Candidate |
| 高风险 | 结构、跨层、跨页、格式、整话或多个阶段的变化 | 先确认，再分阶段 Candidate |

常规对话默认只开放当前元素、当前画格或当前展示单元。明确的画布级请求最多覆盖四个 `PresentationUnit`；整话操作只能进入 Workflow。读取范围可以大于写入范围，但每个写入目标必须在执行前显式解析并在结果中展示。

### 3.4 外置 Agent、MCP 与 Skill

Lantern 可以接入 Codex 等用户选择的外置 Agent，让它们使用自身的推理、视觉检查和图像生成能力参与创作。外置 Agent 是另一种规划与交互入口，不是拥有额外权限的后端；内置与外置 Agent 通过同一 Agent Gateway 复用 Context Builder、Capability Registry、Task、Candidate 和 revision 校验。

```text
内置 Agent ───────────────┐
                         → Agent Gateway → Agent Core
外置 Agent + Skill → MCP ┘
```

首要接入方向是由 Lantern 提供 MCP Server。MCP 只暴露以下语义能力：

- 根据目标与范围构建只读上下文，并返回固定版本引用和省略说明。
- 查询允许的 Capability、输入约束和风险，执行 dry-run 或受控计划。
- 创建、查询和取消异步任务，提交外部生成结果并登记新的 `AssetVersion`。
- 创建、读取、继续修订和丢弃 Candidate；应用仍由 Lantern 完成权限、确认和 revision 校验。

MCP 不暴露 Prisma、对象存储凭证、任意 LCD 写入或原始 `WorkspaceCommand`。连接使用用户身份与 Project 范围授权，默认最小权限；私有图片只通过短期签名资源传递。外置调用必须记录 actor、客户端、连接与工具版本，幂等、取消、stale 和审计规则与内置 Agent 相同。外部生成的图片只能成为新的资源版本和 Candidate，不能覆盖已有图片。

Lantern Skill 是面向外置 Agent 的版本化使用说明，描述对象语义、范围判断、标准协作流程和 MCP 工具用法。Skill 不拥有权限，不复制 Capability schema，也不能代替用户确认；可执行定义始终由 MCP 工具 schema 和 Capability Registry 提供。Skill 与 MCP 契约需要声明兼容版本，契约不匹配时拒绝写入能力。

## 4. 上下文设计

### 4.1 上下文组成

本轮上下文是为当前决策临时构建的事实集合，不是把整个项目和全部聊天记录塞给模型。它包含四层：

1. **交互上下文**：当前输入、快捷意图、附件、显式引用、选择、当前页面和会话中的有效约束。
2. **执行上下文**：目标对象、base revision、允许的作用范围、保护对象、候选 Capability 及其前置条件。
3. **创作上下文**：相关 StoryboardBeat、前后叙事窗口、角色、场景、道具、风格、参考图片和已确认连续性。
4. **项目基线**：漫画故事核心、世界设定、格式、阅读方向、视觉风格和已启用的 Comic Setting。

画布参考卡位置、侧栏浏览状态、当前视口和最近对话只是辅助信号，不能代替作品对象或显式引用。进入消息、任务或候选的可版本化对象必须固定 `versionId`；签名 URL、临时 UI 状态和未采用的模型输出不能成为长期上下文事实。

### 4.2 目标与范围判断

目标解析按以下证据优先级进行：

1. 用户当前输入中明确指定的目标、范围、排除项和保护项。
2. 本轮显式引用的对象与资源版本。
3. 当前选中的作品对象，以及由它解析出的画格、展示单元和关联分镜。
4. 当前页面、创作焦点和指针位置等弱信号。
5. 最近对话中仍有效、且未被本轮输入覆盖的约束。

证据冲突时不猜测。例如用户说“只改当前格”却同时引用另一页图片，系统需要区分它是修改目标还是参考；如果两种解释会产生不同写入结果，就先追问。没有冲突时采用最小写入范围：当前元素优先于当前画格，当前画格优先于当前展示单元，“从这里往下”只追加锚点之后的内容。

Agent 必须正确保留 LCD 中的对象归属、锚点、裁切、合成层、`zIndex`、阅读顺序和锁定约束。不能根据对象是否越过画格边缘猜测层级，也不能把视觉层级当作阅读顺序。

### 4.3 动态选择流程

Context Planner 按以下步骤构建上下文：

1. 从输入解析期望结果、目标、写入范围、保护约束和不确定项。
2. 选择可能使用的 Capability，并读取每项能力声明的必需上下文。
3. 以目标对象为中心扩展直接关系，例如所属画格、关联分镜、相邻叙事、固定资产版本和页面阅读设置。
4. 按“必需事实 → 显式引用 → 连续性相关 → 会话补充 → 项目背景”排序，在预算内裁剪。
5. 校验所有权、Project 边界、版本、前置条件和冲突；重要缺失无法安全默认时转为追问。
6. 冻结实际发送给模型和工具的 context snapshot，并记录被省略内容及原因。

必需上下文不能因预算被静默丢弃。长章节优先使用目标附近的原始事实、远距离摘要和按需检索；摘要不能覆盖最新的明确作品状态。

| 请求 | 必需上下文 | 常用补充 |
|---|---|---|
| 问答与建议 | 用户输入、当前焦点、相关工作稿事实 | 近期约束、相邻页面 |
| 创建角色或场景 | 用户描述、显式附件、Comic 基线 | 已有同名资产、风格参考 |
| 分镜 | 故事目标、格式、阅读方向、当前叙事锚点 | 角色、场景、前后剧情 |
| 页面编排 | 目标展示单元、已确认分镜、阅读设置、base revision | 相邻页、节奏偏好 |
| 单格生成或精修 | 目标画格或图片、关联分镜、保护约束、固定资源版本 | 前后格、角色、场景、风格、草稿 |
| 对白 | 目标分镜和气泡、角色、现有文字、阅读顺序 | 前后对白、语气与关系 |

### 4.4 快照、解释与调试

每个异步任务保存实际使用的 context snapshot。任务之后只能声称使用了快照中存在的信息。用户界面展示“本次主要参考”“影响范围”和关键省略，不展示完整 Prompt。

`context-debug` 必须调用同一 Context Builder，只读重算客户端输入、解析目标、模型输入和省略项；它不能复制第二套组装规则，也不能创建消息、任务或候选。上下文日志默认只保存对象标识、版本、选择理由、裁剪结果和耗时，不记录长期可访问私有资源 URL 或不必要的完整输入。

## 5. Task、Candidate 与失败恢复

### 5.1 Task

一条消息不等于一个 Task。直接回复、追问和同步确定性编辑不创建 GenerationTask；只有需要异步模型、后台处理、重试、取消或进度追踪的动作才创建。

一个 Task 必须记录：

- 发起方身份、内置或外置通道，以及适用的连接和工具版本。
- 用户意图、结构化目标、作用范围和保护约束。
- base revision、context snapshot 和计划调用的 Capability。
- Provider、模型、尝试次数、幂等键、进度与取消信号。
- 每次尝试的校验结果、输出引用和可理解错误。

P0 保持同一会话同一时间只有一个前台活动任务。幂等键阻止重复提交；重试保留旧尝试记录。重试时如果目标 revision 或关键引用已变化，必须重新构建上下文并创建新的执行，而不能把旧输出套到新工作稿。

任务成功只表示执行和输出校验完成。会改变作品的任务必须进一步保存为合法 Candidate；取消、失败和超时只结束任务，不改变工作稿。Provider Adapter 负责隔离供应商格式，只发送当前任务必要的文字与私有资源。

### 5.2 Candidate

Candidate 至少记录目标、影响范围、变更摘要、base revision、来源任务、固定输入与输出版本、结构化结果或受约束操作，以及 `available`、`applied`、`discarded`、`stale` 生命周期。

Candidate 卡片必须回答四个问题：

- 改了什么，目标在哪里。
- 使用了哪些主要参考，有哪些约束未完全满足。
- 应用后会影响哪些对象，是否作为一个 Undo 单位。
- 当前可以预览、应用、继续修订、丢弃还是重新生成。

多阶段结果不能伪装成一个不可拆分的大候选。每一阶段产生独立、可检查的 Candidate；后续阶段在上一阶段应用后的新 revision 上重新规划。页面布局可另存为 PageVariant，但 PageVariant 不是当前作品，也不替代 Candidate 的首次确认。

### 5.3 一致性与失败

- 模型输出先经过 schema、业务规则、Capability 和 LCD 校验，不能把模型 JSON 直接持久化为作品。
- 身份、服装、道具、空间方向、动作衔接和对白顺序等连续性冲突进入候选说明，不自动改写已确认内容。
- 图片生成和精修创建新的 `AssetVersion`；选区、遮罩、扩图范围、构图或层级关系必须来自用户目标，不根据常见画法擅自推断。
- 资源暂时不可读时保留稳定引用；供应商拒绝、超时或内容安全拦截转成可理解错误。
- 应用 Candidate 的事务任一部分失败时，不创建新 revision；生成资源按引用保留策略清理，不能误删仍被消息、候选或快照引用的版本。

## 6. 分阶段实现

### P0：解禁最小协作循环

目标是让 Agent 在新架构上完成一个真实、可恢复的闭环，而不是恢复旧任务类型。

- 将旧的关键词分流和按 `storyboard`、`page_layout`、`frame_image` 等类型直达处理器的路径，收口为 Interaction Resolver、Context Builder、Tool Planner 与 Capability Executor。
- 实现直接回复、补充信息、确认行动和受控执行四种决策；支持模型调用工具、读取工具结果并在步数上限内继续或结束。
- 建立范围优先的 Context v1：当前输入、显式引用、选择、目标附近分镜、相关资产、项目基线、base revision 与 omitted context。
- 首批闭环覆盖：回答创作问题；缺少目标时追问；创建角色或场景候选；针对当前格生成图片或调整对白；候选预览、应用、继续修订、丢弃；任务停止、失败和重试。
- 只开放少量已有且可验证的 Capability。所有生成结果进入 Candidate；确定性低风险动作只有在原子 Undo 和权限测试完整后才允许直接执行。
- 将 Agent Core 收口为与模型和传输无关的服务；内置调用也经过 Agent Gateway，并记录统一 actor 与审计信息，为外置接入保留稳定边界。
- 对话显示行动说明、关键进度、结果摘要和下一步；恢复页面后可以继续查看任务与未应用候选。
- 删除或永久旁路已经由新闭环覆盖的旧写入路径，确保不存在两个可写主入口。

P0 的验收是：Agent 能可靠地区分“回答、追问、行动”，完成至少一个文字模型工具调用和一个图片生成闭环，且取消、失败、刷新、候选拒绝和 revision 冲突都不改变已确认作品。

### P1：动态上下文与复杂局部创作

目标是让 Agent 根据任务主动寻找恰当上下文，并支持真正有用的局部精修。

- Capability 声明上下文需求；Context Planner 以目标为中心检索故事、相邻格、角色、场景、风格和连续性事实，并在预算内动态取舍。
- 建立可解释的引用排序、摘要、遗漏记录、冲突检测与上下文评估；`context-debug` 与任务 snapshot 保持同源。
- 支持选区、遮罩、扩图、局部重画、对白改写、页面节奏建议和少量多对象计划；原稿与候选可以并排比较。
- 支持候选派生、多个可比较方案，以及最多四个展示单元内的 staged Candidate；每阶段基于最新 revision 继续。
- 提供首批 MCP Server：开放上下文读取、Capability 查询与 dry-run、任务生命周期、外部图片版本登记和 Candidate 暂存；Candidate 应用仍回到 Lantern 用户确认。
- 建立回归集，衡量目标识别、错误修改范围、无效追问、上下文引用准确率、Candidate 应用率和 stale 率。

P1 的验收是：用户不必重复说明关键角色和前后剧情，Agent 仍能解释为什么选择这些参考；“只改指定区域”不会改变范围外对象，复杂请求可以被拆成可独立接受的阶段；外置 Agent 可以完成一次读取上下文、生成资源和暂存 Candidate 的闭环，但不能绕过确认写入作品。

### P2：精修模式与 Workflow

目标是支持跨多轮、跨阶段的深度创作，同时保持用户检查点。

- 开放聚焦精修模式：锁定目标、保护范围和比较基线，连续生成派生候选，并支持回到任一可用方案。
- 建立持久 Workflow：父流程保存目标和阶段图，步骤使用普通 Task、Context snapshot、Capability 与 Candidate；支持暂停、恢复、取消、失败重试和从检查点重规划。
- 覆盖续写、整页重编排、跨页结构、整话分镜到逐格生成等流程；结构与生成分阶段确认，已确认前文默认只读。
- 发布版本化 Lantern Skill，并让外置 Agent 复用精修与 Workflow；需要无界面应用时使用 Lantern 签发的一次性确认凭证，不接受外置 Agent 自报用户已同意。
- 根据创作需求提供“探索多个方向”“保持一致性优先”“局部精修”等策略，但它们只调整规划与上下文权重，不建立另一套作品协议。
- 只有职责具备独立输入输出、评估标准和稳定边界时才拆分专门 Planner；不以 Agent 数量或模型数量作为产品能力。

P2 的验收是：长流程可以中途停止并安全恢复，用户能看懂当前阶段、已确认结果和下一步，修改方向后系统只重做受影响的后续步骤。

## 7. 运行与评估约束

Agent 的正式实现需要同时保留以下可观测信息：决策类型、目标解析证据、写入范围、context snapshot 标识、Capability 计划、校验结果、Candidate 状态和最终 revision。诊断信息用于重放和评估，但不保存模型思维链，也不把完整私有内容写入普通日志。

上线以垂直场景评估，而不是以“模型能回答”作为完成标准。每个开放能力至少验证：目标识别、越界保护、缺失信息处理、工具 schema、取消与重试、stale、候选应用、Undo、工作台/预览/导出一致性。外置接入额外验证 Project 授权隔离、签名资源过期、伪造确认、重复请求、旧版 Skill 和完整审计。任何新 Capability 都先完成编辑器执行与测试，再决定 Agent 是仅观察、可预览还是可执行。
