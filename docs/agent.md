# Agent

Lantern 的 Agent 是漫画编辑器中的创作协作者。它读取当前作品与操作焦点，提供建议、计划和候选，并解释将要影响的对象；它不拥有作品事实，也不能绕过用户确认和编辑器写入边界。

本文维护 Agent 的稳定产品与运行边界、当前运行时收口目标和能力前提状态。可执行输入输出以 [`packages/agent-runtime/src/schemas.ts`](../packages/agent-runtime/src/schemas.ts) 为准，任务与候选持久化以 [`prisma/schema.prisma`](../prisma/schema.prisma) 为准，作品写入仍遵守 [LCD](./lcd.md) 和 `packages/shared` 的命令 schema。

## 1. 协作模式

Agent 的行为归入四种模式：

1. **问答与建议**：只读作品上下文，不创建作品任务。
2. **补充信息**：只追问会实质改变结果、作用范围或安全性的缺失信息。
3. **计划与预览**：说明目标、对象、影响范围、关键参考和预期变化，不写入工作稿。
4. **受控执行**：在允许的能力与范围内产生 Candidate；用户应用后才通过 ChangeSet 进入新 revision。

输入区只保留“创作”和“资产”两个工作焦点。工作焦点用于确定优先上下文与能力范围，不代替 Agent 对具体任务和影响范围的判断：创作覆盖故事、分镜、编排、对白和单格生成或修改，资产覆盖角色、场景、道具、风格和参考图。

局部、目标明确且可恢复的生成可以直接进入候选流程。修改已确认内容、多个对象、整页及以上范围、格式或结构时，必须先确认影响；复杂请求拆成有依赖的阶段，每一阶段基于最新 revision 重新检查上下文并单独确认。

常规对话 Agent 的写入边界是用户明确指定的画布范围。默认只使用当前选择或当前展示单元；一次请求最多覆盖四个 `PresentationUnit`，具体 Capability 可以设置更小上限。范围内的多页或多滚动段可以统一规划和并发生成，结果按展示单元说明影响并形成可独立检查的候选；高风险结构变更仍分阶段应用。

对话 Agent 不创建整话。整话生成未来由独立 Workflow 负责整篇 LCD 规划、并发生成、检查、重试和确认，不依赖当前对话 Agent 的会话与任务编排；它可以复用 LCD、固定资源版本、校验、渲染和保存等底层事实源。

Agent 不得：

- 直接覆盖 WorkingRevision 或 SavedSnapshot。
- 把自然语言解释、对话历史或模型原始输出当作作品事实。
- 生成任意 JSON Patch、任意命令名或未经 schema 校验的作品结构。
- 读取一个范围却静默修改另一个范围。
- 用过期上下文强制覆盖已经变化的目标。

## 2. 上下文

任务上下文由持久化工作稿、当前选择、显式引用和当前输入共同构成。画布参考卡的位置、侧栏浏览状态和最近对话只能提供辅助信号，不能替代作品对象及其固定版本。

### 组装优先级

1. 当前指令中明确的目标、保护范围和显式引用。
2. 当前选择，以及由选择解析出的页面、画格、格内元素和关联 StoryboardBeat。
3. 当前对象前后的局部叙事窗口和已确认作品状态。
4. 与任务直接相关的角色、场景、风格、道具和参考资产。
5. 最近对话中尚未沉淀、但与当前请求直接相关的约束。
6. 漫画级故事核心、世界设定、视觉风格和已启用的创作者自定义设定卡。
7. 其他项目背景。

显式引用必须校验所有权和当前 Project 边界。角色、场景、风格、资产和分镜等可版本化对象进入消息、任务或候选时必须固定 `versionId`；后续更新不能改变旧任务实际读取的内容。

作品对象进入 Agent 上下文时，必须保留 LCD 中实际存在的归属、锚点、合成层、裁切、`zIndex`、阅读顺序、关联画格、重叠策略和锁定约束。Agent 不能根据对象是否越过画格边缘猜测层级，也不能把视觉 `zIndex` 当作阅读顺序。无格图、纸面对白、破格对象和跨页对象必须在上下文中显式区分。

资产上下文只传递类型、名称、完整描述和当前图库的全部固定图片版本；主图仍作为默认版本。漫画级视觉风格的文字规则和全部参考图片共同进入上下文，不要求参考图归入普通资产分类。角色、场景、风格与道具不再维护或拼接第二套类型专用属性。

### 最小上下文

| 请求 | 必须包含 | 按需补充 |
|---|---|---|
| 问答与建议 | 当前工作稿、选择和用户输入 | 相关章节摘要、近期对话 |
| 分镜建议 | 故事目标、格式、阅读方向和当前叙事位置 | 角色、场景、风格和前后剧情 |
| 页面编排 | 已确认分镜、目标展示单元和阅读设置 | 节奏偏好、重点画格和相邻页面 |
| 单格生成或精修 | 明确目标、关联分镜、当前资源版本和 base revision | 前后格、角色、场景、草稿和风格 |
| 对白 | 目标分镜、画格或展示单元，角色和现有对白 | 前后对白、关系和语气约束 |
| 资产整理 | 来源素材、目标资产类型和当前 Project | 已有角色、场景或风格版本 |

必需上下文不能因为输入预算被静默丢弃。长章节使用局部窗口和摘要；未发送、被裁剪或因冲突未采用的重要信息进入 `omittedContext`。用户界面展示易理解的“本次主要参考”和影响范围，不暴露冗长 Prompt 或供应商内部格式。

自定义漫画设定卡是只读上下文来源，不预设内容类型，也不是 Agent 工具。Context Builder 只读取当前用户、当前漫画内已启用且未归档的卡片，并按创作者顺序裁剪；任务保存的 context snapshot 固定当次实际读取的标题与正文。

### 快照与调试

每个生成任务保存实际使用的 context snapshot。任务之后只能声称使用了快照中存在的信息，不能以项目里其他可访问数据补写解释。

`context-debug` 是同一 Context Builder 的只读重算入口，展示客户端输入、模型输入、解析后的工作区和会话信息。它不能复制第二套组装规则，也不能创建消息、任务或候选。修改选择解析、引用、裁剪、对话窗口或任务输入时，必须同步检查 context snapshot schema 和调试输出。

## 3. Task 与 Candidate

只有需要异步生成或受控处理的请求才创建 GenerationTask。直接回答、建议和普通确定性编辑不应为了统一流程而制造任务。

一次会话同一时间只允许一个活动任务。任务必须记录输入、目标、作用范围、base revision、context snapshot、Provider、模型、执行尝试、进度、输出校验和错误；幂等键不能创建重复任务。失败、取消和重试保留可追溯记录，并且都不能改变工作稿。

任务完成不表示作品已经改变。对于会产生作品变化的任务，成功表示合法 Candidate 已保存；Candidate 至少需要说明：

- 目标与影响范围。
- 变化摘要和关键参考。
- base revision、来源任务和固定版本引用。
- 可预览的结构化结果或受约束命令。
- available、applied、discarded 或 stale 等生命周期状态。

应用 Candidate 时必须再次校验所有权、目标和 base revision。目标已经变化且无法安全合并时标记 stale；不提供绕过 revision 校验的强制覆盖。应用由业务 service 将合法结果转换为 WorkspaceChangeSet，在事务中一次性产生新 revision，并形成一个 Undo 单位。

丢弃 Candidate 只改变候选状态。其生成资源只有在不再被工作稿、快照、消息、其他候选、页面方案或参考卡引用时，才能按资源保留策略归档或清理。

## 4. 生成与一致性

模型只负责提出受约束的创作结果，不负责数据库 ID、事务、坐标不变量、作品版本和撤销历史。Provider Adapter 隔离供应商请求与返回格式；模型输出必须先经过 schema、业务规则和 LCD 校验。

生成时按以下顺序使用已确认信息：

- 角色：当前明确变体、固定参考版本、稳定身份特征、前后格状态。
- 场景：当前场景版本、空间关系、固定参考画面、前后格状态。
- 风格：漫画默认、本话约束、当前分镜要求、当前指令。
- 动作与连续性：上一格结束状态、当前动作、下一格衔接要求。

身份、服装、伤口、道具、空间方向、视线、动作轴线和对白顺序出现冲突时，默认提示并进入候选说明，不自动修改已确认内容。涉及多个画格或多个范围时，遵守“计划 → 分阶段 Candidate → 用户确认 → 基于新 revision 继续”。

只向 Provider 发送当前任务必需的文本和私有资源。供应商拒绝、超时、格式错误或校验失败必须转成可理解错误，保留旧内容，并且不能产生空白候选。

图片生成与局部修图是允许的 AI-first 能力，但在轻量图片查看器/编辑器能够提供明确目标、选区或遮罩、前后对比和版本确认后再接入。生成与修图只能产生新的 `AssetVersion` 和局部替换 Candidate，不直接覆盖原图；确定性的移动、缩放和裁切继续由编辑器 Capability 完成。

### 透明抠图与叠图

抠图范围、保留的孔洞与细节、边缘软硬、光晕、叠图范围、锚点以及各层是否同步移动，都由用户想要的画面效果和对象关系决定。Agent 不能从“人物出格”“物品出格”或某种常见构图推导固定部位、固定层数或固定处理方式；信息不足且不同选择会明显改变结果时，先用画面语言确认用户要保留和遮挡什么。

根据目标和源图条件选择合成方式：

- **透明抠图**：需要保留主体自身的白色、灰阶、网点或不透明填充时，生成带 alpha 的新 `AssetVersion`，再按目标关系放入 Frame 或 `UnitOverlay`。
- **同源叠图**：同一画面需要同时受裁切和越界显示时，可以保留格内底图并叠加同源透明层；只有需要联动的层才共享坐标基准、裁切参考和变换，用户明确需要错位、分离或独立运动时允许拆开。
- **线稿混合**：纯白底漫画线稿只需叠加黑线与网点时，可使用 `multiply` 避免细线抠图损失；白色区域必须遮挡下层、背景不是稳定白色或需要真实透明导出时，改用 alpha 抠图。
- **重新生成或扩图**：源图没有被遮挡区域的信息，或目标要求改变动作、透视、光照和前后关系时，先补全或重新生成画面，再执行抠图与合成；这是一种可选路径，不是边缘不理想时的固定结论。

透明抠图采用以下通用技术流程，具体参数按画风、分辨率和目标效果调整：

1. 根据用户选区、语义描述或实例分割得到目标 mask，建立“确定前景 / 确定背景 / 待求边缘”的 trimap；不要仅用全图明度阈值判断黑白漫画前景，否则背景网点和浅灰阴影会被误保留。
2. 对 mask 做按输出分辨率折算的腐蚀与膨胀。普通不透明区域只在 trimap 的边缘带求 alpha matte；细发丝、线稿、透明或半透明材质则扩大待求区域，并结合局部边缘、颜色和线条连通性细化。
3. 使用连通域和从确定背景开始的 flood fill 清理外部残留，并识别主体内部孔洞；孔洞保留、闭合或半透明由目标效果决定，不把“空隙越多”或“轮廓越实”当作固定质量标准。
4. 在较高分辨率生成 matte，再下采样获得抗锯齿；对前景颜色做 unpremultiply 和边缘去污染，按需要使用轻量 edge contract、feather 或 despill。白边、灰边和锯齿应消除，但用户需要的柔光、描边或风格化光晕作为独立效果层保留，不与抠图修边混在一起。
5. 合成前校准源图与叠图的坐标、裁切和变换；在透明棋盘、白色、中灰和实际页面背景上分别检查 100% 尺寸与最终显示尺寸，并用工作台、阅读预览和导出确认同一结果。

Agent 上下文和 Candidate 摘要需要说明目标对象、采用的抠图或混合方式、锚定与层级关系、是否联动以及主要边缘处理；多层共同表达一个效果时作为一个复合结果预览和应用，但不把它们永久推断为不可独立编辑的单一对象。

未来新增能力必须先成为编辑器可验证的领域能力，明确输入 schema、作用范围、风险、预览和撤销策略，再决定 Agent 是否只能观察、可以预览或允许执行。Agent 不以专项模块或模型数量为目标；只有职责具备独立契约、独立评估和稳定业务边界时才拆分。

## 6. 运行时收口

当前 Agent Runtime 仍按 storyboard、page_layout、frame_image、asset_parse 和 dialogue 等任务类型组织，部分处理器会直接形成整组分镜或大范围页面替换；Orchestrator 主要从文本判断任务与范围，尚未从统一 Capability Registry 规划受控工具。这些旧执行路径保持冻结，不能作为后续 Agent 的主路径。

目标执行路径是：

```text
用户输入 + 当前选择 + 显式引用
  → Context Builder
  → Intent / Scope Resolver
  → Planner（只输出工具计划）
  → Capability Registry 权限与 schema 校验
  → Dry-run Executor + LCD Validator + Diff Summary
  → Candidate / Staged Candidates
  → 用户预览与应用
  → WorkspaceChangeSet → 新 WorkingRevision
```

会话、消息与历史读取、候选管理、stale 检查和 revision 冲突保护继续保留；这些现有结构是否进入新 Agent 架构，应在重构时重新判断。确定性导出继续读取已保存版本，不依赖模型决策。

新工具链完成前，旧 AI 对话和非确定性任务创建保持硬冻结，不提供环境变量或运行模式开关。交互入口与任务服务都会拒绝 storyboard、page_layout、frame_image、asset_parse 和 dialogue 等旧任务，不能构建上下文、投递 Worker 或创建新 Candidate；已有会话、历史记录和 Candidate 不受影响。确定性 export 任务与独立页面下载继续可用。

进入受控执行前必须满足：

- 页面、画格、气泡等首批结构动作具备同源 Capability、Undo 和测试。
- 共享场景投影能够一致支持工作台、预览和导出所需的层级、可见性、坐标与裁切语义。
- allowlist 默认只开放当前对象或当前展示单元；明确的画布级任务最多开放四个展示单元。
- Agent 能解释实际读取的上下文、计划工具、影响对象和省略信息。
- dry-run 能在不写数据库时返回校验结果、视觉预览和变更摘要。
- 图片查看器/编辑器能够为图片生成和局部修图提供目标、选区或遮罩、前后对比和版本确认。
- 旧执行路径不能与新执行器同时成为可写主路径。

首批闭环至少覆盖以下代表性场景：

| 场景 | 计划方式 | 用户结果 |
|---|---|---|
| 给当前格新增对白 | 新增气泡并绑定对白 | 只影响当前格，可调整、应用和撤销 |
| 拆分画格 | 拆分结构并重新计算阅读顺序 | 先预览分隔与序号，一次应用 |
| 角色或物体破框 | 按目标选择透明抠图、同源叠图或线稿混合，再建立对应覆盖层和锚定关系 | 复合预览通过后一次应用，层间联动方式与用户目标一致 |
| 开场跨页大图 | 形成跨页结构并迁移关联内容 | 高风险分阶段确认，可中途停止 |
| 增加条漫停顿 | 调整纵向空间并进行手机视区预览 | 保持连续阅读，不修改格内图片 |
| 只重画一格 | 生成新 AssetVersion 并局部替换 | 原图保留，只更新指定元素引用 |

## 7. 漫画编辑与 Agent 能力矩阵

本表是对话 Agent 的能力前提和状态索引，不重新定义产品需求。用户能力与验收仍由产品需求、编辑器体验和 LCD 负责；本表只跟踪能力是否具备用户入口、实现路径，以及是否已登记为 Agent 可见 Capability。未来独立的整话生成 Workflow 不在本表范围内。

新增、删除或调整漫画编辑能力，或改变用户入口、Capability 登记和 Agent 权限时，必须同步更新本表。当前状态以 [`packages/shared/src/lcd/`](../packages/shared/src/lcd/)、[`workspace-schema.ts`](../packages/shared/src/workspace-schema.ts)、[`capabilities.ts`](../packages/editor-core/src/capabilities.ts) 和实际入口为准。

矩阵按创作编排的依赖梯度排列；`核心`约覆盖常见页面创作的 50%-60%，`增强`将覆盖推进到约 70%-80%，`后置`不阻塞首批 Agent。表末的`AI 专属`只收纳必须由模型产出结果的能力；其余能力既可由创作者直接操作，也可在未来由 Agent 通过同源 Capability 协助完成。

- `结构`表示由 LCD 和确定性 Capability 持续编辑；`混合`表示结构化限定范围后，由模型或图像 SDK 产出可预览 Candidate；`图像`表示效果进入新的 AssetVersion 或透明效果资产，不为每种画内效果增加协议类型。
- `已接入`、`部分接入`、`未接入`描述当前用户入口。`已登记（禁用）`表示 Capability 已存在但 Agent 尚不可调用；当前没有任何漫画编辑 Capability 对 Agent 开放执行。
- 对话 Agent 不直接生成或覆盖整页 LCD。布局只生成少量结构候选，生成和精修只替换指定资源版本，所有结果均可比较、拒绝和撤销。
- 确定性用户入口统一提供选择反馈、菜单、一次撤销和必要的删除确认；页漫与条漫共享 ChangeSet、Candidate、PageVariant 和 Snapshot，不建立格式专用版本机制。
- 跨层能力按提升到 Unit Overlay、收回 Frame、转为 Unit 对象、重新锚定、允许叠格和调整合成顺序等漫画语义登记，不向 Agent 暴露任意父节点或坐标补丁。同一容器内的单对象确定性调整可以按低风险能力规划；跨层、叠格、跨页和多对象结构变化必须形成 Candidate，多阶段变化逐段确认。
