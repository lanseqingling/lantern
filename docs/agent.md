# Agent

Lantern 的 Agent 是漫画编辑器中的创作协作者。它读取当前作品与操作焦点，提供建议、计划和候选，并解释将要影响的对象；它不拥有作品事实，也不能绕过用户确认和编辑器写入边界。

本文维护 Agent 的稳定产品与运行边界。可执行输入输出以 [`packages/agent-runtime/src/schemas.ts`](../packages/agent-runtime/src/schemas.ts) 为准，任务与候选持久化以 [`prisma/schema.prisma`](../prisma/schema.prisma) 为准，作品写入仍遵守 [LCD](./lcd.md) 和 `packages/shared` 的命令 schema。

## 1. 协作模式

Agent 的行为归入四种模式：

1. **问答与建议**：只读作品上下文，不创建作品任务。
2. **补充信息**：只追问会实质改变结果、作用范围或安全性的缺失信息。
3. **计划与预览**：说明目标、对象、影响范围、关键参考和预期变化，不写入工作稿。
4. **受控执行**：在允许的能力与范围内产生 Candidate；用户应用后才通过 ChangeSet 进入新 revision。

局部、目标明确且可恢复的生成可以直接进入候选流程。修改已确认内容、多个对象、整页及以上范围、格式或结构时，必须先确认影响；复杂请求拆成有依赖的阶段，每一阶段基于最新 revision 重新检查上下文并单独确认。

Agent 不得：

- 直接覆盖 WorkingRevision 或 SavedSnapshot。
- 把自然语言解释、对话历史或模型原始输出当作作品事实。
- 生成任意 JSON Patch、任意命令名或未经 schema 校验的作品结构。
- 读取一个范围却静默修改另一个范围。
- 用过期上下文强制覆盖已经变化的目标。

## 2. 上下文

任务上下文由持久化工作稿、当前选择、显式引用和当前输入共同构成。画布参考卡的位置、侧栏浏览状态和最近对话只能提供辅助信号，不能替代作品对象及其固定版本。

### 组装优先级

1. 当前指令中明确的目标、保护范围和显式引用。
2. 当前选择，以及由选择解析出的页面、画格、格内元素和关联 StoryboardBeat。
3. 当前对象前后的局部叙事窗口和已确认作品状态。
4. 与任务直接相关的角色、场景、风格、道具和参考资产。
5. 最近对话中尚未沉淀、但与当前请求直接相关的约束。
6. 其他项目背景。

显式引用必须校验所有权和当前 Project 边界。角色、场景、风格、资产和分镜等可版本化对象进入消息、任务或候选时必须固定 `versionId`；后续更新不能改变旧任务实际读取的内容。

### 最小上下文

| 请求 | 必须包含 | 按需补充 |
|---|---|---|
| 问答与建议 | 当前工作稿、选择和用户输入 | 相关章节摘要、近期对话 |
| 分镜建议 | 故事目标、格式、阅读方向和当前叙事位置 | 角色、场景、风格和前后剧情 |
| 页面编排 | 已确认分镜、目标展示单元和阅读设置 | 节奏偏好、重点画格和相邻页面 |
| 单格生成或精修 | 明确目标、关联分镜、当前资源版本和 base revision | 前后格、角色、场景、草稿和风格 |
| 对白 | 目标分镜或画格、角色和现有对白 | 前后对白、关系和语气约束 |
| 资产整理 | 来源素材、目标资产类型和当前 Project | 已有角色、场景或风格版本 |

必需上下文不能因为输入预算被静默丢弃。长章节使用局部窗口和摘要；未发送、被裁剪或因冲突未采用的重要信息进入 `omittedContext`。用户界面展示易理解的“本次主要参考”和影响范围，不暴露冗长 Prompt 或供应商内部格式。

### 快照与调试

每个生成任务保存实际使用的 context snapshot。任务之后只能声称使用了快照中存在的信息，不能以项目里其他可访问数据补写解释。

`context-debug` 是同一 Context Builder 的只读重算入口，展示客户端输入、模型输入、解析后的工作区和会话信息。它不能复制第二套组装规则，也不能创建消息、任务或候选。修改选择解析、引用、裁剪、对话窗口或任务输入时，必须同步检查 context snapshot schema 和调试输出。

## 3. Task 与 Candidate

只有需要异步生成或受控处理的请求才创建 GenerationTask。直接回答、建议和普通确定性编辑不应为了统一流程而制造任务。

一次会话同一时间只允许一个活动任务。任务必须记录输入、目标、作用范围、base revision、context snapshot、Provider、模型、执行尝试、进度、输出校验和错误；幂等键不能创建重复任务。失败、取消和重试保留可追溯记录，并且都不能改变工作稿。

任务完成不表示作品已经改变。对于会产生作品变化的任务，成功表示合法 Candidate 已保存；Candidate 至少需要说明：

- 目标与影响范围。
- 变化摘要和关键参考。
- base revision、来源任务和固定版本引用。
- 可预览的结构化结果或受约束命令。
- available、applied、discarded 或 stale 等生命周期状态。

应用 Candidate 时必须再次校验所有权、目标和 base revision。目标已经变化且无法安全合并时标记 stale；不提供绕过 revision 校验的强制覆盖。应用由业务 service 将合法结果转换为 WorkspaceChangeSet，在事务中一次性产生新 revision，并形成一个 Undo 单位。

丢弃 Candidate 只改变候选状态。其生成资源只有在不再被工作稿、快照、消息、其他候选、页面方案或参考卡引用时，才能按资源保留策略归档或清理。

## 4. 生成与一致性

模型只负责提出受约束的创作结果，不负责数据库 ID、事务、坐标不变量、作品版本和撤销历史。Provider Adapter 隔离供应商请求与返回格式；模型输出必须先经过 schema、业务规则和 LCD 校验。

生成时按以下顺序使用已确认信息：

- 角色：当前明确变体、固定参考版本、稳定身份特征、前后格状态。
- 场景：当前场景版本、空间关系、固定参考画面、前后格状态。
- 风格：漫画默认、本话约束、当前分镜要求、当前指令。
- 动作与连续性：上一格结束状态、当前动作、下一格衔接要求。

身份、服装、伤口、道具、空间方向、视线、动作轴线和对白顺序出现冲突时，默认提示并进入候选说明，不自动修改已确认内容。涉及多个画格或多个范围时，遵守“计划 → 分阶段 Candidate → 用户确认 → 基于新 revision 继续”。

只向 Provider 发送当前任务必需的文本和私有资源。供应商拒绝、超时、格式错误或校验失败必须转成可理解错误，保留旧内容，并且不能产生空白候选。

## 5. 实现入口

| 事实 | 来源 |
|---|---|
| 上下文组装与调试快照 | [`context-builder.ts`](../packages/agent-runtime/src/context-builder.ts) |
| 交互决策与安全收口 | [`orchestrator.ts`](../packages/agent-runtime/src/orchestrator.ts) |
| Agent 与 Candidate 可执行 schema | [`schemas.ts`](../packages/agent-runtime/src/schemas.ts) |
| 任务创建、幂等、取消与重试 | [`task-service.ts`](../packages/agent-runtime/src/task-service.ts) |
| Worker 处理与候选持久化 | [`task-processor.ts`](../packages/agent-runtime/src/task-processor.ts) |
| 任务、尝试、消息引用与候选字段 | [`prisma/schema.prisma`](../prisma/schema.prisma) |
| 作品命令、ChangeSet 与 LCD 校验 | [`packages/shared`](../packages/shared/src) |

未来新增能力必须先成为编辑器可验证的领域能力，明确输入 schema、作用范围、风险、预览和撤销策略，再决定 Agent 是否只能观察、可以预览或允许执行。Agent 不以专项模块或模型数量为目标；只有职责具备独立契约、独立评估和稳定业务边界时才拆分。
