# 产品计划

本文维护 Lantern 可动态调整的产品目标与后续计划。它用于记录值得继续推进的问题、方向和预期效果，不定义当前产品事实，不构成版本范围、MVP 验收或交付承诺。

计划条目彼此独立，可以随判断变化新增、删除、拆分、合并、调整优先级或改变状态。本文不按固定阶段组织，也不要求长期保留固定数量的计划。实现进入产品后，应把最终规则同步到对应正式文档和能力矩阵；本文只保留仍有规划价值的内容。

## PLAN-001 故事来源与独立分镜稿

| 属性 | 内容 |
|---|---|
| 类型 | 创作流程 |
| 优先级 | P0 |
| 状态 | 待规划 |
| 目标 | 让用户在创建页面和画格之前，先把故事整理为可编辑、可确认、可继续编排的一话分镜稿。 |

### 当前基础

- 漫画已经具备简介、故事核心、世界设定和视觉风格等漫画级创作基线。
- 章节已经具备标题与梗概，工作稿可以保存独立的 StoryboardBeat 及其版本。
- 用户可以为已有画格创建或编辑单个分镜条目的标题和画面描述。
- 单格分镜修改可以通过 Candidate 进入确认与版本生命周期。

### 当前问题

- 故事来源尚未成为工作台中的可编辑对象，漫画简介、章节梗概和单格描述之间缺少可追踪的内容来源。
- 分镜条目依附于已有画格，用户需要先创建页面和画格，再倒序补充分镜。
- 分镜列表只能定位和编辑既有条目，不能完整承担独立创建、插入、删除、拆分、合并和重排。
- Agent 只处理唯一目标画格的单个分镜条目，不能先提出一话级分镜方案再交给用户整体调整。

### 规划方向

- 增加章节级轻量故事来源，由可排序、可版本化的文本段落组成，不扩展为必须维护的剧情树或复杂设定表。
- 允许 StoryboardBeat 在尚未分配页面和画格时独立存在，并维护清楚的叙事顺序和编排状态。
- 在工作台提供分镜稿视图，支持创建、插入、删除、拖动排序、拆分、合并和批量调整。
- 允许分镜固定引用故事段落版本，使用户能理解分镜来自哪部分故事；更新来源时不静默改写已确认分镜。
- 允许外部 Agent 把整话或指定故事范围拆解为分镜候选，通过 AgentDraft 和 ChangeProposal 统一审查。
- 保持分镜表达轻量。结构化信息优先通过引用关系和界面组织表达，不把镜头、情绪、角色和场景全部变成强制表单字段。

### 预期效果

- 用户可以从一段故事直接进入分镜整理，而不需要先理解页面和画格工具。
- 故事调整、分镜调整和页面重编排彼此解耦，未受影响的内容保持稳定。
- Agent 能在正式出图之前协助检查叙事完整性、节奏和镜头覆盖，减少后期返工。

### 观察信号

- 一段完整章节故事可以形成一组尚未编排的分镜，并在创建页面之前完成编辑和确认。
- 分镜拆分、合并和重排不会丢失故事引用、已有对白草稿或已经固定的创作参考。
- 用户可以明确区分故事来源、分镜叙事、页面布局和格内成稿。

### 暂不包含

- 重型剧情树、时间线数据库或人物关系图。
- 强制用户在开始创作前完成全部世界观和角色设定。
- 一键生成并直接覆盖整话正式作品。

## PLAN-002 多页生产看板与页面布局编排

| 属性 | 内容 |
|---|---|
| 类型 | 漫画工作台 |
| 优先级 | P0 |
| 状态 | 待规划 |
| 目标 | 把已经确认或正在调整的分镜快速组织为可阅读、可继续精修的多页漫画骨架。 |

### 当前基础

- 工作台已经提供页面缩略图、正文页、封面页、过场页、单页、真正双页和条漫滚动段。
- 页面支持创建、命名、复制、逐页移动、插入、合并、拆分和删除。
- 画格支持创建、复制、删除、移动、缩放、斜切、出血、叠格、跨页和层级调整。
- 页面和画格修改通过统一 Capability 进入可撤销工作稿。

### 当前问题

- 新增正文页仍从空白页面开始，没有常用页面骨架或布局预设。
- 分镜列表与页面列表彼此分离，不能直接看出分镜分配到了哪一页、哪一格，或哪些分镜尚未编排。
- 缺少整话视角的批量分页、重点格安排、翻页点设计和多页结构调整。
- 阅读顺序虽会随创建与复制维护，但缺少独立、清楚的检查和调整入口。
- 页面卡主要表达当前查看和工作稿状态，不能帮助用户判断哪些页面待编排、待出图、待排字或待确认。

### 规划方向

- 在现有工作台增加可切换的章节编排视图，不引入自由节点画布或独立流程后台。
- 以页面卡组织一话内容，每张卡直接展示已分配的分镜、画格数量、重点格、阅读顺序和当前创作状态。
- 支持在未编排分镜、页面和画格之间拖动分配，允许跨页移动并保留稳定对象关系。
- 提供少量高覆盖率页面骨架，例如单格满版、上大下二、三格递进、四格网格和重点格加辅助格；模板只生成可继续编辑的画格结构。
- 让外部 Agent 根据分镜数量、叙事重点和阅读方向提出分页与布局候选，再复用现有页面和画格 Capability 形成真实作品结构。
- 支持选中若干页面进行批量编排、重新分页或状态调整，高风险结果继续通过方案审查进入工作稿。

### 预期效果

- 用户从分镜稿进入页面编排时，不再需要逐页、逐格从空白状态手工搭建。
- 页面结构和叙事节奏在出图前可见、可比较、可撤回。
- 长章节可以在同一视图中识别缺失内容和当前推进位置，减少在页面缩略图之间反复定位。

### 观察信号

- 一组分镜可以形成多页布局候选，并在应用后得到真实、可编辑的页面和画格。
- 用户能在整话视角调整分页、重点格和翻页点，同时保留未受影响页面的图片和文字。
- 分镜、页面和画格之间的归属与未编排状态始终可见。

### 暂不包含

- 替代专业排版软件的复杂嵌套、全功能图层面板或印前设置。
- 需要用户手动连接的自由节点式漫画工作流。
- 自动决定且无法修改的整话布局。

## PLAN-003 外部 Agent 的任务化编排与接入体验

| 属性 | 内容 |
|---|---|
| 类型 | Agent 协作 |
| 优先级 | P0 |
| 状态 | 待规划 |
| 目标 | 让用户从工作台清楚地把当前创作范围交给外部 Agent，并持续理解任务目标、进度、结果和恢复方式。 |

### 当前基础

- Lantern 已通过 MCP 暴露作品查询、固定资源、页面、画格、图片、对白、旁白和编排等受控语义能力。
- 配套 Skill 已提供作品语义、漫画编排知识、创作契约和检查方法。
- 外部 Agent 的一话编辑进入隔离 AgentDraft，完成后冻结为 ChangeProposal，不直接改动正式工作稿。
- 工作台可以展示外部 Agent 活动、定位目标对象，并从历史入口审查方案。
- 工作台批注可以把无绑定正文和零到多个页面、画格、图片、对白、旁白、效果或纸面坐标引用交给外部 Agent，并把处理状态、说明和最终方案带回同一列表。

### 当前问题

- 设置页以安装命令和外部文档为主，不能直接确认外部 Agent、MCP 和 Skill 是否已经正确连接和同步。
- 批注已经解决具体画面问题的精确交接，但非批注型整页、整话任务仍需要用户在外部 Agent 中自行组织目标、范围和关键参考。
- 外部活动根据 MCP 操作推断为任务，缺少显式的任务目标、计划阶段、预计产物和完成条件。
- 活动详情默认接近技术日志，包含工具名、事件名、固定资源 ID 和结果 JSON，不能直接表达创作进展。
- 多页任务需要大量低层能力调用，容易产生重复上下文读取、版本冲突和难以恢复的中间状态。
- 外部宿主中断或活动超时后，Lantern 只能陈述观察事实，不能帮助用户理解保留了什么、应从哪里继续。

### 规划方向

- 在设置页显示外部 Agent 接入状态，包括可识别的宿主、MCP 健康状态、Skill 或能力版本、测试连接和重新同步入口。
- 在现有批注交接之外，为非批注型任务提供“交给外部 Agent”入口，根据当前漫画、章节、页面、选择对象和显式参考形成结构化任务简述与稳定范围链接。
- 为外部协作增加显式任务协议，至少表达开始、进度、完成和失败，并记录目标、作用范围、计划步骤、当前步骤和预期产物。
- 整页、整话、多对象和其他高风险任务在执行前展示可理解的计划和影响范围；用户确认的是创作行动，不是底层工具调用。
- 活动面板默认显示创作阶段、目标对象、完成数量、失败位置和方案入口；技术字段只在诊断详情中展示。
- 为分镜批量创建、页面骨架、批量资源登记与放置等高频组合增加合适的高层 Capability，减少低层循环调用，但仍复用统一领域能力和版本校验。
- 外部宿主无法被 Lantern 强制取消时，明确区分“停止接受后续写入”“保留当前草稿”和“继续外部任务”，不伪装成已经终止宿主进程。

### 预期效果

- 外部 Agent 从开发者接入方式变成普通创作者可理解的产品能力。
- 用户始终知道 Agent 正在处理什么、影响哪里、已经形成哪些结果，以及失败后如何继续。
- 多页任务减少重复读取和版本冲突，AgentDraft 中的连续编辑更稳定。

### 观察信号

- 用户能在产品内确认外部 Agent 接入是否可用，并从当前创作位置完成一次准确交接。
- 工作台能按用户目标展示外部任务进度，而不是只显示 MCP 事件流水。
- 单个步骤失败时，已完成草稿保持可检查，用户能从明确位置继续或冻结现有方案。

### 暂不包含

- Lantern 托管所有外部 Agent 的运行进程。
- 在工作台中复制外部 Agent 的完整聊天产品。
- 以复杂流程图要求普通用户维护 Prompt、工具节点和模型参数。

## PLAN-004 资产与分镜的显式一致性绑定

| 属性 | 内容 |
|---|---|
| 类型 | 创作上下文 |
| 优先级 | P1 |
| 状态 | 候选 |
| 目标 | 把需要保持一致的人物、场景、道具和视觉风格变成可见、固定、可追踪的生成参考。 |

### 当前基础

- 资产空间已经支持角色、场景、道具、参考资料、派生形态、多图片槽和固定 AssetVersion。
- 故事核心、世界设定和视觉风格作为漫画级创作基线进入 Agent 上下文。
- 用户可以显式引用资产，MCP 也可以读取固定原图并在结果中保持稳定版本映射。
- 作品和历史版本固定引用具体资源版本，不受资产后续更新静默影响。

### 当前问题

- 分镜主要用标题和自然语言描述表达内容，没有显式说明本格应使用哪个角色形态、场景、道具或风格图片版本。
- 同一资产存在多张图片时，具体任务使用哪一张参考主要依赖主图、用户 Prompt 或 Agent 自行判断。
- 用户不能从章节或分镜直接查看当前关键参考是否齐全，也不能从资产反向查看它被哪些页面和分镜使用。
- “保持角色一致”仍然主要是自然语言要求，不是可以检查的任务输入。

### 规划方向

- 为章节、分镜和页面增加轻量资源引用，固定到具体 AssetVersion，并通过用途标签区分出场角色、主要场景、关键道具和风格参考。
- 提供本话角色与场景集合，支持批量分配到连续分镜或页面；具体分镜可以覆盖章节默认引用。
- 在分镜卡和页面卡展示关键参考标签、固定版本和缺失状态，不要求用户维护复杂角色属性表。
- 外部 Agent 执行生成、修改和一致性检查时优先使用显式固定引用，并在方案中说明实际使用的关键参考。
- 在资产详情中提供使用位置，帮助用户判断更新、派生或归档的影响范围。

### 预期效果

- 一致性从难以验证的 Prompt 期望变成可见的上下文约束。
- 用户能够为不同叙事时期、服装或场景状态选择稳定版本，同时保留同一角色或场景身份。
- Agent 不需要反复猜测当前页面应该使用哪张参考图。

### 观察信号

- 用户能把某个角色形态批量绑定到一段连续分镜，并在单格中显式覆盖。
- 生成或修改方案能说明每格使用的角色、场景和风格版本。
- 调整资产主图不会静默改变已经固定的分镜、工作稿和保存快照。

### 暂不包含

- 专属一致性模型训练或自动微调。
- 为每种资产建立不同的重型属性表。
- 承诺底层图片模型绝对保持人物或画风一致。

## PLAN-005 Agent 方案的差异解释与返修闭环

| 属性 | 内容 |
|---|---|
| 类型 | 方案审查 |
| 优先级 | P1 |
| 状态 | 候选 |
| 目标 | 让用户快速理解 Agent 方案改变了什么，并从已有方案继续局部返修，而不是在整体应用和整体丢弃之间二选一。 |

### 当前基础

- 正式版本和 Agent 方案进入统一历史列表，并保留各自不可变基线。
- 对比画布可以并排展示当前版本与目标版本，定位有差异的展示单元。
- 用户可以应用并保存、保留或丢弃方案；过期方案需要显式确认覆盖风险。
- 应用方案原子创建正式 WorkingRevision 和 SavedSnapshot，不改写历史版本。

### 当前问题

- 对比页主要依赖最终画面，页面名称、分镜、阅读顺序、资源引用等非视觉变化不容易被解释。
- 方案缺少整体验证摘要，用户需要逐页确认影响范围，难以快速发现失败、未完成或没有实际成稿的页面。
- 一个只包含页面重命名的方案也可能只显示“当前展示单元有差异”，左右画面本身无法说明变化来源。
- 冻结方案只能应用、保留或丢弃，不能把满意部分作为基线交给 Agent，只返修指定页面或画格。

### 规划方向

- 为方案生成结构化变更摘要，展示任务目标、影响范围、变化页面、画格结构、图片、对白、分镜、资源引用、失败项和未完成项。
- 在页面导航中区分视觉差异、结构差异和文字或元数据差异，并允许直接跳到对应对象。
- 保留左右视觉对比，同时增加面向创作者的变更清单；内部命令和字段只进入诊断详情。
- 增加“继续修改方案”，以冻结方案为基线创建新的 AgentDraft，保留满意结果并只修改用户指定的页面或对象。
- 在局部返修稳定前，不急于提供任意命令级部分合并；优先保证新草稿的基线、范围和最终原子应用清楚可靠。

### 预期效果

- 用户可以快速判断一个多页方案是否完整、是否符合目标，以及主要风险在哪里。
- 不满意的局部结果不会迫使用户丢弃整项任务或先应用再手工修复。
- Agent 协作形成“方案—审查—局部返修—再次审查—应用”的持续闭环。

### 观察信号

- 方案入口能先给出受影响页面和变化类型摘要，再进入逐页视觉对比。
- 纯结构或文字变化即使画面相同，也能被用户准确理解。
- 用户能基于一个多页方案只返修指定页面，未指定页面在新方案中保持不变。

### 暂不包含

- 任意跨版本、跨对象的通用合并编辑器。
- 自动替用户决定哪些变化应该接受。
- 绕过方案冻结、revision 校验和用户应用动作的快捷写入。

## 计划条目模板

新增计划时，在汇总表添加一行，并复制以下结构。不存在适合的类型、状态或描述字段时，可以直接调整；模板不是固定 schema。

```markdown
## PLAN-XXX 计划标题

| 属性 | 内容 |
|---|---|
| 类型 | 开放标签 |
| 优先级 | 当前相对优先级 |

### 当前基础

- 已经存在且可以复用的能力。

### 当前问题

- 基于产品现状观察到的问题。

### 规划方向

- 可能的产品方向，不在此固定最终协议或实现方案。

### 预期效果

- 用户和产品应该获得的变化。

### 观察信号

- 用于判断方向是否有效的行为或结果，不作为发布验收承诺。

### 暂不包含

- 当前计划有意排除的范围。
```

## 维护方式

- 汇总表是当前计划索引，条目标题、类型、优先级和状态变化时同步更新对应行。
- 计划按当前优先级和理解组织，不按固定阶段、版本或时间线排列。
- 新问题可以直接新增计划；一个计划过大时可以拆分，方向重叠时可以合并。
- 已失效、被否定或已经完整进入正式产品规则的计划可以直接删除；历史原因由版本历史保留，不在本文累积过程记录。
- 计划进入实施并改变用户能力时，最终规则写入产品需求、能力矩阵、编辑器、LCD 或 Agent 等对应事实源，不能继续以本文代替正式产品定义。
- 当前基础与当前问题是规划时的现状摘要。实现变化后应及时修正或删除，避免把旧判断长期保留为现状。
